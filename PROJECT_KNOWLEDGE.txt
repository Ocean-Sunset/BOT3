# Prowl - Discord Bot & Dashboard

## Overview
Prowl is a Discord bot with a web dashboard. Two runtime components sharing one database:
- **Bot** (`cli/`): Python, discord.py, always-on on hidencloud
- **Website** (`website/`): FastAPI + Jinja2, deployed to Vercel

## Database: Turso (libSQL/SQLite)
Migrated from Neon PostgreSQL to Turso (libSQL engine, not Turso DB).
- **Bot**: `pyturso` with embedded replica (local `prowl.db` file, synced to cloud every 60s)
- **Website**: `libsql` remote HTTP access (stateless, no local file)
- Both SDKs are synchronous — all DB calls wrapped in `asyncio.to_thread()`

### Environment Variables
- `TURSO_DATABASE_URL` — e.g. `libsql://prowl-yourorg.turso.io`
- `TURSO_AUTH_TOKEN` — auth token from Turso dashboard

### Schema Setup
```powershell
$env:TURSO_DATABASE_URL="libsql://..."
$env:TURSO_AUTH_TOKEN="..."
python website\api\setup_schema.py
```
Run once to create all tables in Turso.

### Key Differences from PostgreSQL
- No `JSONB` — columns are `TEXT`, parsed as JSON in Python
- `$N` asyncpg placeholders → `?` SQLite placeholders
- `jsonb_set()` → `json_set()` (libSQL built-in)
- No `::jsonb` casts, no `extract(epoch from ...)`, no `SERIAL PRIMARY KEY`
- `TRUE/FALSE` → `1/0`
- `BOOLEAN DEFAULT TRUE` → `INTEGER DEFAULT 1`
- `DOUBLE PRECISION` → `REAL`
- `ANY($N::text[])` → `IN` clause

## Repo Layout
- `cli/` — Discord bot (Python, discord.py). Deployed to hidencloud via `deploy-bot` branch
- `website/` — Dashboard + API (FastAPI, Jinja2). Deployed to Vercel from `website` branch
- `whitebots.online/` — Static landing page (unrelated)

## Git Rules
- **Always work on and push to `website` branch. Never touch `main`.**
- Vercel deploys `website`. The `deploy-bot` branch is auto-generated from `cli/**` by GitHub Action
- After touching `cli/**`, the deploy-bot Action rebuilds automatically — bot server needs to pull the new build
- Never commit `.env` / secrets

## CSS Cache-Busting
Every template links CSS with `?v=N`. When you edit a CSS file, you MUST bump the `?v=` number in every template that references it.

## Save-Bar Pattern
Dashboard pages use pending/original/LOADED/SETTINGS_SNAPSHOT:
- `markChanged(key, value)` stores original, sets pending, mutates snapshot, shows save bar
- On save: delete `original[key]`, update `LOADED[key]`, clear `pending[key]`
- On discard: rebuild from `LOADED`, overlay `original` for keys still in `pending`

## Custom Dropdowns
`.md-custom-select` dropdowns are absolutely positioned. Never bind the same dropdown twice.

## API Conventions
- Settings live in per-feature tables (`*_settings(guild_id, settings TEXT, updated_at)`)
- `_save_settings()` + `_sanitize_setting()` handle validation
- Snowflake/channel keys must end in `_channel`, `_channel_id`, `_id`, or `_role`
- API endpoints: `require_guild_access(request, guild_id)` at the top
- Bot cogs read settings via `neon_db.parse_settings(row["settings"], DEFAULTS)`

## Bot Conventions
- Every `.py` in `cli/components/` auto-loads (unless `_`-prefixed)
- Intents in `cli/Ediscord/variables.py` — message logging needs `message_content` intent
- All bot feature defaults must match between `cli/components/<feature>.py` and `website/api/index.py`
- Windows is case-insensitive; Linux deploy is not — keep import paths case-exact

## DB Files
- `cli/Ediscord/db.py` — Bot DB module (pyturso embedded replica)
- `website/api/db.py` — Website DB module (libsql remote HTTP)
- `website/api/setup_schema.py` — Schema creation script
- `website/api/index.py` — Main website API (~3758 lines)
- `cli/start.py` — Bot entry point
- `cli/components/*.py` — Bot feature cogs
- `website/api/session.py` — Session store

## Deployment
- Bot server: hidencloud, pulls from `deploy-bot` branch
- Website: Vercel, deploys from `website` branch
- After DB migration: run `pip install pyturso libsql` on bot server, set env vars on both
